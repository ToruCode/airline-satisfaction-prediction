# 航空会社の顧客満足度予測 | Airline Satisfaction Prediction

## 1. プロジェクト概要

Kaggleのコンペティション「Predicting Airline Satisfaction（Playground Series - Season 6, Episode 10）」に参加し、航空会社の顧客満足度を予測する二値分類モデルを構築しました。

顧客属性、搭乗時のサービス評価、フライトの遅延情報などを用いて、探索的データ分析（EDA）からモデル構築、ハイパーパラメータ最適化、特徴量エンジニアリング、モデル評価、Kaggleへの提出まで実施しました。

**コンペティション：** https://www.kaggle.com/competitions/playground-series-s6e10

## 3. データセット

Kaggleが提供する航空会社の顧客満足度データを使用しました。

- 学習データ：約70万件
- テストデータ：約30万件
- 目的変数：`satisfaction`
- 説明変数：21項目（元データ）

主な説明変数は以下のとおりです。

- 顧客属性
- 旅行目的・搭乗クラス
- 機内Wi-Fiサービス評価
- オンライン搭乗手続きの評価
- 座席の快適性
- 機内エンターテインメントの評価
- 出発・到着遅延時間

## 4. 分析・開発の流れ

### 4.1 探索的データ分析（EDA）

目的変数の分布、欠損値、数値変数・カテゴリ変数の特徴を確認しました。

また、顧客満足度と各サービス評価、遅延時間の関係を分析し、モデル構築に向けた仮説を検討しました。

### 4.2 統計分析

ロジスティック回帰を用いて、遅延時間やサービス評価と顧客満足度の関係を分析しました。

オッズ比などを確認し、各変数が満足度とどのように関連しているかを検討しました。

※観察データに基づく関連性の分析であり、因果効果を示すものではありません。

### 4.3 機械学習モデルの構築

以下のモデルを構築・比較しました。

1. Logistic Regression
2. LightGBM
3. CatBoost

LightGBMではOptunaによるハイパーパラメータ最適化を実施しました。

モデル評価には主にROC-AUCを使用しました。

### 4.4 特徴量エンジニアリング

既存の特徴量から新しい特徴量を作成し、予測精度への影響を検証しました。

検討した特徴量の例：

- `service_min`：サービス評価の最小値
- `service_std`：サービス評価の標準偏差
- `delay_recovery`：到着遅延時間と出発遅延時間の差
- `delay_per_distance`：飛行距離に対する到着遅延時間

特徴量を追加したモデルと元のモデルを比較し、さらに特徴量を除外するアブレーション実験を行いました。

### 4.5 アンサンブル学習

LightGBMとCatBoostの予測確率を重み付き平均するアンサンブルを検証しました。

重みを段階的に変更し、ROC-AUCの推移を比較しました。

今回の検証では、LightGBM単独の方が良好な結果となりました。

## 5. モデル評価結果

### 検証データでの比較

| モデル | ROC-AUC | Log Loss |
|---|---:|---:|
| LightGBM（Optuna最適化・21特徴量） | 0.966060 | 0.216478 |
| LightGBM（25特徴量） | 0.966447 | 0.215964 |
| LightGBM（選択した3特徴量を追加） | 0.966494 | 0.215953 |

特徴量エンジニアリングによって、検証データ上のROC-AUCがわずかに改善しました。

ただし、検証データ上での改善がKaggleの未知データでも再現されるとは限らないため、Public Leaderboardの結果も確認しました。

### Kaggle Public Leaderboard

| 提出モデル | Public ROC-AUC |
|---|---:|
| LightGBM（21特徴量） | **0.95819** |
| LightGBM（全学習データで再学習・21特徴量） | 0.95792 |
| LightGBM（特徴量追加モデル） | 0.95783 |

今回の提出結果では、最初のLightGBMモデルが最も高いPublic Scoreを記録しました。

なお、Public Leaderboardはテストデータの一部に基づく評価であり、最終的なPrivate Leaderboardの結果とは異なる可能性があります。

## 6. 考察

今回の分析から、以下の知見が得られました。

- LightGBMは高い予測性能を示した。
- 特徴量エンジニアリングによる改善は限定的だった。
- CatBoostとの単純な重み付きアンサンブルでは精度改善が見られなかった。
- 全学習データでの再学習が、必ずしもPublic Scoreの向上につながるわけではなかった。
- 検証データとPublic Leaderboardの結果には差があり、モデルの汎化性能を慎重に評価する必要がある。

特に、複雑なモデルや特徴量を追加するだけでなく、実験結果に基づいて手法を採用・不採用とする重要性を学びました。
